## چند روش برای نوشتن رنگ

```css
.demo {
  color: tomato;
  color: #1d4ed8;
  color: #1d4ed8cc;
  color: rgb(29 78 216);
  color: rgb(29 78 216 / 0.8);
  color: hsl(224 76% 48%);
}
```

### نام رنگ

برای نمونه‌های سریع خوانا است:

```css
color: tomato;
```

### Hex

شش رقم برای کانال‌های رنگ دارد و در بسیاری از طراحی‌ها رایج است. شکل هشت‌رقمی می‌تواند شفافیت را نیز مشخص کند.

### RGB

```css
color: rgb(29 78 216);
color: rgb(29 78 216 / 0.8);
```

وقتی کنترل کانال‌ها یا شفافیت برای شما مهم است، RGB مناسب است.

### HSL

```css
color: hsl(224 76% 48%);
```

HSL رنگ را با Hue، Saturation و Lightness بیان می‌کند. برای ساختن طیف روشن‌تر و تیره‌تر یک رنگ، تغییر Lightness می‌تواند مفید باشد.

## کنتراست

رنگ فقط مسئله زیبایی نیست. متن باید روی پس‌زمینه خوانا باشد. در جزوه، معیار راهنمای WCAG برای متن معمولی حداقل نسبت کنتراست ۴.۵ به ۱ ذکر شده است.

رنگ را تنها راه انتقال معنا قرار ندهید؛ مثلاً خطا را فقط با قرمز مشخص نکنید و از متن یا نشانه دیگری هم استفاده کنید.

## تمرین

یک رنگ اصلی انتخاب کنید و با HSL سه نسخه روشن‌تر و تیره‌تر از آن بسازید؛ سپس دو ترکیب متن/پس‌زمینه را در DevTools بررسی کنید.

## مدل ذهنی رنگ در مرورگر

وقتی `color` را می‌نویسید، مرورگر فقط یک «کد رنگ» نمی‌بیند؛ مقدار نهایی بعد از Cascade، وراثت و محاسبه‌ی CSS مشخص می‌شود. بنابراین در DevTools همیشه هم قانون نوشته‌شده و هم مقدار `Computed` را بررسی کنید.

سه سؤال عملی برای هر رنگ:

1. این رنگ متعلق به **متن، پس‌زمینه، border یا state** است؟
2. آیا در حالت `hover`، `focus` و `disabled` هنوز قابل تشخیص است؟
3. آیا معنا فقط با رنگ منتقل شده یا متن/آیکون/الگوی دیگری هم وجود دارد؟

## Alpha با opacity یکی نیست

این دو رفتار یکسان نیستند:

```css
.badge {
  background: rgb(37 99 235 / 0.2);
}

.card {
  opacity: 0.8;
}
```

در حالت اول فقط رنگ پس‌زمینه شفاف است. در حالت دوم کل عنصر و محتوای آن، از جمله متن و فرزندان، تحت تأثیر opacity قرار می‌گیرند. برای ساخت overlay معمولاً شفافیت خود رنگ کنترل‌پذیرتر است.

## ساخت Palette به‌جای انتخاب رنگ‌های تصادفی

در یک پروژه واقعی بهتر است چند نقش مشخص داشته باشید:

```css
:root {
  --color-primary: #2563eb;
  --color-primary-strong: #1d4ed8;
  --color-surface: #ffffff;
  --color-text: #172033;
  --color-muted: #64748b;
  --color-danger: #b91c1c;
}
```

بعد کامپوننت‌ها از **نقش** رنگ استفاده می‌کنند، نه اینکه هرجا یک Hex جدید بسازند. این موضوع در درس Design Tokens عمیق‌تر می‌شود.

## Hover، Focus و وضعیت‌های معنایی

یک دکمه نباید فقط در حالت عادی رنگ مناسبی داشته باشد:

```css
.button {
  background: var(--color-primary);
  color: white;
}

.button:hover {
  background: var(--color-primary-strong);
}

.button:focus-visible {
  outline: 3px solid #f59e0b;
  outline-offset: 3px;
}
```

کنتراست را برای هر state مهم بررسی کنید، نه فقط حالت عادی.

## دیباگ رنگ با DevTools

یک عنصر را انتخاب کنید و سه چیز را بررسی کنید: قانون خط‌خورده در تب Styles، مقدار نهایی در Computed، و نمونه‌ی رنگ/contrast در ابزارهای مرورگر. اگر رنگ مورد انتظار دیده نمی‌شود، قبل از تغییر Hex به Cascade و Specificity نگاه کنید.

### تمرین دیباگ

کد زیر را اصلاح کنید تا متن هم در حالت عادی و هم در حالت hover خوانا بماند و focus نیز قابل مشاهده باشد:

```css
a { color: #e2e8f0; background: #ffffff; }
a:hover { color: #ffffff; background: #f8fafc; }
```

اول مشکل را توضیح دهید، بعد رنگ‌ها را تغییر دهید و با ابزار contrast مرورگر نتیجه را بررسی کنید.

## معیار تسلط

اگر بتوانید تفاوت `rgb(... / alpha)` و `opacity` را توضیح دهید، یک palette نقش‌محور بسازید، contrast را بررسی کنید و یک مشکل رنگی را با DevTools پیدا کنید، این درس را فقط حفظ نکرده‌اید؛ آن را فهمیده‌اید.
