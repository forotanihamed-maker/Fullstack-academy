## بخش A: HTML مقدماتی

### ۲.۱ HTML چیست؟ `[ضروری]`

**مفهوم.** HTML مخفف HyperText Markup Language است. یک زبان نشانه‌گذاری است، یعنی با آن به مرورگر می‌گوییم هر تکه از محتوا «چیست»: عنوان، پاراگراف، لینک، تصویر، فرم و غیره.

HTML زبان برنامه‌نویسی نیست. متغیر، شرط و حلقه ندارد. منطق را JavaScript اضافه می‌کند.

**ساختار یک المان (Element):**

```html
<p class="intro">سلام دنیا</p>
```

```
<p class="intro">   سلام دنیا   </p>
 |   |                |          |
 |   attribute        content    closing tag
 opening tag
```

تگ باز (`<p>`)، تگ بسته (`</p>`) و محتوا در بینشان، روی هم یک المان می‌سازند.

بعضی المان‌ها محتوا ندارند و تگ بسته هم ندارند. به آن‌ها **Void Element** می‌گویند: `<br>`، `<hr>`، `<img>`، `<input>`، `<meta>`، `<link>`.

المان‌ها می‌توانند داخل هم قرار بگیرند (Nesting) و درخت DOM همین‌طور ساخته می‌شود:

```html
<p>این یک <strong>مهم</strong> است.</p>
```

**اشتباهات رایج**

- **فراموش کردن تگ بسته.** HTML بسیار «بخشنده» است و خطا نمی‌دهد، ولی نتیجه‌ی نمایش خراب می‌شود و پیدا کردن علتش سخت است.
- **بستن نادرست تو در تو:** `<p><strong>متن</p></strong>` غلط است. هر تگی که آخر باز شده، باید اول بسته شود.
- **اعتماد به اینکه «در مرورگر درست نشان می‌دهد» یعنی کد درست است.** از اعتبارسنج رسمی (`validator.w3.org`) استفاده کن.

**تمرین کوچک:** المان‌های این قطعه را بشمار و بگو کدام Void است و کدام در کدام تو در تو شده:

```html
<p>سلام <em>دنیا</em><br>خوش آمدی</p>
```

### ۲.۲ ساختار یک سند HTML `[ضروری]`

**مفهوم.** هر صفحه‌ی HTML یک قالب ثابت دارد. مرورگر انتظار دارد این اجزا را ببیند:

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>صفحه‌ی اول من</title>
  </head>
  <body>
    <h1>سلام</h1>
    <p>این اولین صفحه‌ی من است.</p>
  </body>
</html>
```

**توضیح خط‌به‌خط:**

| بخش | توضیح |
|-----|-------|
| `<!DOCTYPE html>` | به مرورگر می‌گوید سند HTML5 است. بدون آن، مرورگر در «Quirks Mode» رندر می‌کند و رفتارهای قدیمی و غیرمنتظره می‌بیند. تگ نیست، یک اعلان است. |
| `<html lang="fa" dir="rtl">` | ریشه‌ی سند. `lang` زبان صفحه را مشخص می‌کند (برای screen reader، ترجمه‌ی خودکار و SEO) و `dir` جهت متن را. |
| `<head>` | اطلاعات درباره‌ی صفحه (نمایش داده نمی‌شود). |
| `<meta charset="UTF-8">` | کدگذاری کاراکترها. بدون آن ممکن است فارسی به شکل کاراکترهای به‌هم‌ریخته دیده شود. باید در ۱۰۲۴ بایت اول فایل باشد، پس اولین مورد داخل `head` بگذار. |
| `<meta name="viewport" ...>` | برای موبایل لازم است. بدون آن صفحه روی موبایل مثل دسکتاپ کوچک‌شده نمایش داده می‌شود. جزئیات در بخش پیشرفته. |
| `<title>` | عنوان تب مرورگر، Bookmark و نتایج جستجو. |
| `<body>` | هر چیزی که کاربر می‌بیند. |

**تفاوت `head` و `body`:** `head` برای مرورگر و موتور جستجو است، `body` برای کاربر. تنها چیز داخل `head` که کاربر مستقیم می‌بیند، `title` در تب است.

**اشتباهات رایج**

- فراموش کردن `<!DOCTYPE html>` یا `charset`.
- گذاشتن محتوای قابل‌نمایش در `head`.
- ننوشتن `lang` (برای فارسی `fa`، برای انگلیسی `en`).
- مقدار یکسان `title` در همه‌ی صفحه‌های یک سایت.

**تمرین کوچک:** یک فایل `index.html` با ساختار بالا بساز. `title` را عوض کن و تغییرش را در تب مرورگر ببین. بعد `charset` را حذف کن و ببین چه می‌شود (ممکن است در بعضی مرورگرها فارسی خراب نشود، چون حدس می‌زنند، ولی به آن تکیه نکن).

### ۲.۳ Heading، پاراگراف و متن `[ضروری]`

**Heading:** `h1` تا `h6` برای عنوان‌گذاری سلسله‌مراتبی. `h1` مهم‌ترین، `h6` کم‌اهمیت‌ترین.

```html
<h1>آموزش وب</h1>
<h2>HTML</h2>
<h3>تگ‌های متنی</h3>
<h2>CSS</h2>
```

**پاراگراف:** `<p>`.

**قوانین مهم:**

- Heading برای معنا است، نه برای بزرگ‌کردن فونت. اندازه را با CSS تعیین می‌کنیم.
- سلسله‌مراتب را نشکن: بعد از `h2` مستقیم `h4` نگذار.
- توصیه‌ی رایج: در هر صفحه یک `h1` که موضوع اصلی صفحه را بگوید.

**فضای خالی (Whitespace) در HTML:** چند Space و Enter پشت‌سرهم، فقط یک فاصله نمایش داده می‌شوند:

```html
<p>سلام      به
   همه</p>
```

نتیجه: «سلام به همه» (در یک خط، با یک فاصله). برای جدا کردن بخش‌ها از پاراگراف جدید استفاده کن، نه Enter.

**المان‌های متنی رایج:**

| المان | معنی | نکته |
|-------|------|------|
| `<strong>` | اهمیت زیاد | معمولاً Bold نمایش داده می‌شود |
| `<em>` | تأکید | معمولاً Italic |
| `<b>` / `<i>` | فقط ظاهر یا نقش خاص (مثلاً نام محصول، اصطلاح) | منسوخ نیستند، ولی برای «اهمیت» از `strong` و `em` استفاده کن |
| `<br>` | شکستن خط | فقط برای شعر، آدرس و مواردی که شکستن خط جزو محتواست |
| `<hr>` | جداکننده‌ی موضوعی | |
| `<code>` | قطعه کد | |
| `<pre>` | حفظ فاصله‌ها و Enterها | برای بلوک‌های کد |
| `<blockquote>` | نقل‌قول بلند | |
| `<small>` | متن فرعی | مثلاً حقوق کپی‌رایت |

**Entities (نویسه‌های ویژه):** برای نمایش خودِ کاراکترهای `<` و `>` و `&` در متن:

```html
<p>برای نوشتن تگ پاراگراف از &lt;p&gt; استفاده کن.</p>
<p>&amp; علامت «و» است.</p>
```

> **ارتباط با فصل‌های بعد:** همین مسئله (تفاوت «متن» و «کد HTML») ریشه‌ی حمله‌ی XSS است (فصل Security).

**اشتباهات رایج**

- استفاده از `<br><br>` به جای فاصله‌گذاری (کار CSS است).
- انتخاب Heading بر اساس اندازه‌ی ظاهری.
- استفاده از `<b>` به جای `<strong>` وقتی منظور «مهم بودن» است.

**تمرین کوچک:** یک مقاله‌ی کوتاه درباره‌ی خودت بنویس با یک `h1`، دو `h2` و چند پاراگراف. در یکی از پاراگراف‌ها کلمه‌ای را با `strong` و کلمه‌ی دیگر را با `em` مشخص کن.

### ۲.۴ لینک‌ها `[ضروری]`

**Syntax:**

```html
<a href="https://example.com">رفتن به سایت</a>
```

**انواع `href`:**

```html
<!-- لینک خارجی (آدرس کامل) -->
<a href="https://developer.mozilla.org">MDN</a>

<!-- لینک نسبی به صفحه‌ای در همین پروژه -->
<a href="about.html">درباره‌ی ما</a>
<a href="pages/contact.html">تماس</a>
<a href="../index.html">بازگشت به خانه</a>

<!-- پرش به بخشی از همین صفحه (با id) -->
<a href="#faq">سؤالات متداول</a>
<h2 id="faq">سؤالات متداول</h2>

<!-- ایمیل و تلفن -->
<a href="mailto:info@example.com">ارسال ایمیل</a>
<a href="tel:+989120000000">تماس تلفنی</a>

<!-- باز شدن در تب جدید -->
<a href="https://example.com" target="_blank" rel="noopener noreferrer">سایت (تب جدید)</a>
```

**مسیر مطلق و نسبی:**

| نوع | مثال | کاربرد |
|-----|------|--------|
| مطلق (Absolute) | `https://site.com/a.html` | سایت‌های دیگر |
| نسبی (Relative) | `css/style.css`، `../img/a.png` | فایل‌های داخل پروژه |

`../` یعنی «یک پوشه بالاتر برو».

**نکات مهم**

- `target="_blank"` را با احتیاط استفاده کن؛ تب جدید برای همه خوشایند نیست. مرورگرهای مدرن به‌طور پیش‌فرض رفتار `noopener` را اعمال می‌کنند، ولی نوشتن `rel="noopener noreferrer"` عادت خوبی است.
- متن لینک باید خودش معنا بدهد: «مشاهده‌ی قیمت‌ها» به‌جای «اینجا کلیک کنید». (screen readerها لیست لینک‌ها را جدا می‌خوانند.)
- لینک برای رفتن به یک آدرس است. اگر کاری انجام می‌دهی (ارسال، باز کردن منو)، المان درست `<button>` است (بخش ۲.۷).

**اشتباهات رایج**

- استفاده از آدرس فایل لوکال مثل `C:\Users\...` در `href`. فقط روی کامپیوتر خودت کار می‌کند.
- اشتباه در مسیر نسبی (حروف بزرگ و کوچک، پوشه‌ها). در سرور لینوکس `Image.PNG` با `image.png` فرق دارد.
- نداشتن متن در لینکی که فقط یک آیکون دارد (در بخش Accessibility می‌بینی).

**تمرین کوچک:** دو فایل `index.html` و `about.html` بساز و بینشان لینک بده. بعد در `index.html` یک لینک به یک Heading پایین همان صفحه بساز.

### ۲.۵ تصاویر `[ضروری]`

**Syntax:**

```html
<img src="images/cat.jpg" alt="گربه‌ی خاکستری روی مبل" width="400" height="300" />
```

| Attribute | وظیفه |
|-----------|-------|
| `src` | آدرس تصویر (الزامی) |
| `alt` | متن جایگزین (الزامی در عمل) |
| `width` / `height` | ابعاد ذاتی تصویر، برای جلوگیری از «پرش» صفحه هنگام بارگذاری |

**`alt` برای چه است؟** (۱) screen reader آن را می‌خواند، (۲) اگر تصویر لود نشد نمایش داده می‌شود، (۳) موتور جستجو از آن می‌فهمد تصویر چیست. اگر تصویر تزئینی محض است، `alt=""` (خالی) بگذار، نه حذف کامل.

**فرمت‌ها:**

| فرمت | مناسب برای |
|------|------------|
| JPG | عکس‌ها |
| PNG | تصاویر با شفافیت و جزئیات تیز |
| AVIF / WebP | جایگزین مدرن و سبک‌تر برای JPG و PNG |
| SVG | آیکن و لوگو (برداری، بدون افت کیفیت) |

**اشتباهات رایج**

- حذف `alt` یا نوشتن `alt="image"` / `alt="عکس"`.
- بارگذاری عکس چندمگابایتی برای نمایش در اندازه‌ی کوچک.
- نوشتن متن مهم (مثل قیمت) داخل تصویر.

**تمرین کوچک:** دو تصویر در صفحه بگذار: یکی که محتوای مهم دارد (`alt` توصیفی) و یکی صرفاً تزئینی (`alt=""`).

### ۲.۶ لیست‌ها `[ضروری]`

```html
<!-- لیست بدون ترتیب -->
<ul>
  <li>HTML</li>
  <li>CSS</li>
  <li>JavaScript</li>
</ul>

<!-- لیست مرتب -->
<ol>
  <li>نصب VS Code</li>
  <li>ساخت پوشه‌ی پروژه</li>
  <li>اجرای Live Server</li>
</ol>

<!-- لیست توصیفی -->
<dl>
  <dt>DOM</dt>
  <dd>نمایش درختی صفحه در مرورگر</dd>
  <dt>CSSOM</dt>
  <dd>نمایش درختی استایل‌ها</dd>
</dl>
```

**لیست تو در تو:** زیرلیست باید داخل یک `li` باشد، نه مستقیم زیر `ul`:

```html
<ul>
  <li>Front-End
    <ul>
      <li>HTML</li>
      <li>CSS</li>
    </ul>
  </li>
  <li>Back-End</li>
</ul>
```

ویژگی‌های `ol`: `start="5"` (شروع از ۵)، `reversed` (معکوس)، `type="a"`.

**نکته:** منوی ناوبری هم از نظر معنایی «لیستی از لینک‌ها» است، پس معمولاً با `ul` ساخته می‌شود (در بخش Semantic می‌بینی).

**اشتباهات رایج**

- `ul` مستقیم داخل `ul` (بدون `li` والد).
- استفاده از `ul` فقط برای ایجاد تورفتگی.
- استفاده از `<br>` و شماره‌ی دستی به‌جای `ol`.

**تمرین کوچک:** لیست «مراحل رزرو بلیت» را با `ol` بساز و برای یکی از مراحل یک زیرلیست `ul` اضافه کن.

### ۲.۷ دکمه‌ها `[ضروری]`

```html
<button type="button">ذخیره</button>
<button type="submit">ارسال</button>
<button type="reset">پاک کردن</button>
<button type="button" disabled>غیرفعال</button>
```

| `type` | رفتار |
|--------|-------|
| `button` | هیچ کاری نمی‌کند (برای JavaScript) |
| `submit` | فرم را ارسال می‌کند (پیش‌فرض داخل فرم!) |
| `reset` | مقدارهای فرم را به حالت اول برمی‌گرداند |

**تفاوت `a` و `button`:**

| | `<a>` | `<button>` |
|---|-------|------------|
| هدف | رفتن به یک آدرس | انجام یک عمل |
| مثال | «مشاهده‌ی محصول» | «افزودن به سبد»، «باز کردن منو» |
| فعال‌سازی با کیبورد | Enter | Enter و Space |

**اشتباه رایج:** داخل `form` نوشتن `<button>` بدون `type` و تعجب از اینکه فرم ارسال می‌شود (پیش‌فرض `submit` است). ساخت دکمه با `div` هم ممنوع است، چون focus و کیبورد و screen reader را از دست می‌دهی.

**تمرین کوچک:** سه دکمه با سه `type` بساز. کدام داخل فرم صفحه را Refresh می‌کند؟ (جواب را با امتحان بفهم.)

### ۲.۸ کامنت‌ها `[ضروری]`

```html
<!-- این یک کامنت است و نمایش داده نمی‌شود -->
<p>متن قابل‌مشاهده</p>

<!--
  کامنت چندخطی
  برای توضیح بخش بزرگ
-->
```

**نکته:** کامنت‌ها برای هر کسی که «Source View» بزند قابل‌دیدن‌اند. رمز، توکن و اطلاعات حساس در آن‌ها ننویس. از کامنت برای توضیح «چرا» استفاده کن، نه تکرار «چه».

### ۲.۹ Attribute، class و id `[ضروری]`

Attribute اطلاعات اضافه به المان می‌دهد و همیشه در تگ باز می‌آید:

```html
<a href="about.html" title="صفحه‌ی درباره‌ی ما" class="link" id="about-link">درباره</a>
```

Attributeهای سراسری (Global) پرکاربرد:

| Attribute | کاربرد |
|-----------|--------|
| `id` | شناسه‌ی یکتا |
| `class` | گروه‌بندی برای استایل و JS (قابل تکرار) |
| `title` | راهنمای tooltip (به آن برای اطلاعات حیاتی تکیه نکن) |
| `lang` | زبان یک بخش از متن |
| `hidden` | مخفی کردن المان |
| `tabindex` | کنترل ترتیب Tab (بخش Accessibility) |
| `data-*` | داده‌ی دلخواه (بخش پیشرفته) |

**Attribute Boolean:** وجودش یعنی «روشن»، نیازی به مقدار نیست: `required`، `disabled`، `checked`، `hidden`.

**`class` در برابر `id`:**

| | `id` | `class` |
|---|------|---------|
| تکرار در صفحه | ممنوع (یکتا) | مجاز |
| چند مقدار روی یک المان | خیر | بله: `class="card featured"` |
| کاربرد | لینک به بخش، اتصال `label`، انتخاب یک المان خاص در JS | استایل‌دهی و انتخاب گروهی |

```html
<div class="card featured">...</div>
<div class="card">...</div>
<h2 id="pricing">قیمت‌ها</h2>
```

**نام‌گذاری:** انگلیسی، حروف کوچک، با خط تیره (`card-product`). نام را بر اساس نقش بگذار، نه ظاهر: `warning` بهتر از `text-red`.

**اشتباهات رایج**

- دو المان با `id` یکسان (JS و لینک‌ها رفتار نامعلوم پیدا می‌کنند).
- نوشتن `class="a" class="b"` (فقط اولی اعمال می‌شود. درست: `class="a b"`).
- نام‌گذاری بر اساس ظاهر.

**تمرین کوچک:** سه `div` با کلاس مشترک `card` بساز و فقط به یکی کلاس دوم `featured` بده. یک `h2` با `id` بساز و از بالای صفحه به آن لینک بده.

### ۲.۱۰ Block، Inline، div و span `[ضروری]`

**Block:** کل عرض را می‌گیرد و از خط جدید شروع می‌شود: `div`، `p`، `h1`..`h6`، `ul`، `section`.

**Inline:** فقط به اندازه‌ی محتوا جا می‌گیرد و در ادامه‌ی خط می‌آید: `span`، `a`، `strong`، `em`، `img`.

```html
<div>این یک بلوک است</div>
<div>این هم یک بلوک است (خط جدید)</div>

<span>این اینلاین است</span> <span>و این هم در همان خط</span>
```

`div` و `span` المان‌های بدون معنا هستند: `div` برای گروه‌بندی بلوکی و `span` برای گروه‌بندی درون‌خطی، وقتی المان معنادارتری وجود ندارد.

> **قانون طلایی:** اول دنبال المان معنادار بگرد (`article`، `ul`، `button`، `nav` ...). فقط اگر وجود نداشت، سراغ `div` و `span` برو. (دلیلش در بخش متوسط.)

**ارتباط با CSS:** خاصیت `display` که در فصل CSS می‌آید، همین رفتار Inline/Block را تغییر می‌دهد.

### تمرین‌های HTML مقدماتی

**ساده**

1. ساختار کامل یک سند HTML را بدون نگاه کردن بنویس.
2. یک لیست خرید با `ul` و یک لیست مراحل پخت با `ol` بساز.
3. سه تصویر با `alt` مناسب قرار بده.

**متوسط**

1. دو صفحه‌ی `index.html` و `about.html` با ناوبری دوطرفه بساز.
2. در یک صفحه‌ی طولانی، فهرست پرش (لینک‌هایی که با `#id` به Headingهای پایین می‌روند) بساز.

**چالشی**

1. صفحه‌ی خودت را در `validator.w3.org` بررسی کن و همه‌ی خطاها و هشدارها را رفع کن.

### پروژه‌ی سطح HTML مقدماتی: «صفحه‌ی معرفی شخصی چندصفحه‌ای»

- **هدف:** ساخت یک وب‌سایت کوچک ۳ صفحه‌ای (خانه، درباره‌ی من، علاقه‌مندی‌ها) فقط با HTML.
- **امکانات:** ناوبری بین صفحه‌ها در هر صفحه؛ عنوان و معرفی؛ حداقل یک لیست مرتب و یک لیست نامرتب؛ حداقل دو تصویر؛ یک لینک خارجی؛ یک لینک `mailto`؛ فهرست پرش به بخش‌های همان صفحه در صفحه‌ی طولانی‌تر.
- **مهارت‌ها:** ساختار سند، Headingها، لینک‌های نسبی، تصویر، لیست، `id`.
- **محدودیت‌ها:** بدون CSS و JavaScript؛ بدون `div` و `span` (هنوز لازم نیستند)؛ بدون استفاده از `<br>` برای فاصله‌گذاری.
- **معیار قبولی:**
  - هر سه صفحه در `validator.w3.org` بدون خطا باشند.
  - `title` هر صفحه یکتا و توصیفی باشد.
  - همه‌ی تصاویر `alt` درست داشته باشند.
  - هیچ لینک خرابی نباشد.
  - سلسله‌مراتب Headingها در هر صفحه درست باشد.

### پاسخنامه‌ی مختصر (پس از تلاش خودت ببین)

**سؤال ۷:** خروجی در مرورگر معمولاً یک لیست با تورفتگی نمایش می‌دهد، ولی ساختار نامعتبر است، چون `ul` فقط باید `li` را مستقیم داشته باشد؛ زیرلیست باید داخل `li` باشد.

**سؤال ۸:** پاراگراف اول «سلام دنیا» در یک خط (فاصله‌ها و Enterها یکی می‌شوند)؛ دومی در دو خط (به خاطر `br`).

**سؤال ۹:** نبود `DOCTYPE`، `lang`، `head`/`charset`/`title`؛ پرش از `h1` به `h4`؛ مسیر محلی `C:\...`؛ `img` بدون `alt`؛ متن لینک «اینجا کلیک کن»؛ `id` تکراری.
