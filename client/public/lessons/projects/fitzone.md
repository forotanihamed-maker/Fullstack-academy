# FitZone — Landing Page فروش تجهیزات ورزشی

> **سطح:** مبتدی تا متوسط  
> **مرحله:** HTML و CSS  
> **زمان پیشنهادی:** ۳ تا ۵ روز  
> **پیش‌نیاز:** فصل ۲ (HTML) و فصل ۳ (CSS)

## هدف

ساخت یک Landing Page مدرن و تمیز برای فروش تجهیزات ورزشی؛ فقط با HTML و CSS (بدون JavaScript و بدون فریم‌ورک). این پروژه اولین جایی است که همه‌ی چیزهای فصل HTML و CSS را در یک صفحه‌ی واقعی کنار هم می‌گذاری.

**چیزی که با این پروژه یاد می‌گیری:** پایه‌ی واقعی HTML، CSS و Responsive Design.

## ساختار صفحه

```text
┌─ Header / Navbar ────────────────────────────┐
│  لوگو        لینک‌ها...         [دکمه‌ی اصلی]  │
├─ Hero ───────────────────────────────────────┤
│  تیتر بزرگ + توضیح کوتاه + دکمه‌ی CTA + تصویر │
├─ ویژگی‌ها ────────────────────────────────────┤
│  [کارت] [کارت] [کارت] [کارت]                  │
├─ محصولات ─────────────────────────────────────┤
│  [محصول] [محصول] [محصول] [محصول]              │
├─ CTA ─────────────────────────────────────────┤
│  یک دعوت به اقدام نهایی                       │
├─ Footer ──────────────────────────────────────┤
│  لینک‌ها، تماس، کپی‌رایت                      │
└───────────────────────────────────────────────┘
```

## امکانات (Requirements)

- **Header / Navbar:** لوگو، منوی ناوبری، یک دکمه‌ی اصلی. در موبایل منو باید قابل‌استفاده بماند (می‌توانی منوی ساده‌ی افقی یا فهرست عمودی بسازی؛ منوی همبرگری با JavaScript لازم نیست).
- **Hero Section:** تیتر `h1` واضح، توضیح کوتاه، دکمه‌ی CTA و یک تصویر.
- **بخش ویژگی‌ها:** ۳ تا ۴ کارت (مثلاً کیفیت، ارسال سریع، ضمانت، پشتیبانی).
- **محصولات:** ۴ تا ۶ کارت محصول (تصویر، نام، قیمت، دکمه).
- **CTA:** یک بخش دعوت به اقدام قبل از Footer.
- **Footer:** لینک‌ها، اطلاعات تماس و کپی‌رایت.
- **CSS Variables** برای رنگ‌ها، فاصله‌ها، فونت و شعاع گوشه.
- **Responsive Design** با Media Query و رویکرد Mobile-First.

## مهارت‌هایی که تمرین می‌شود

- ساختار استاندارد و Semantic HTML (`header`، `nav`، `main`، `section`، `article`، `footer`)
- Flexbox و Grid
- متغیرهای CSS و ساخت یک سیستم رنگ و فاصله‌ی یکدست
- Media Query و Mobile-First
- تصاویر واکنش‌گرا (`max-width`، `object-fit`، `alt`)
- طراحی بصری: فاصله، سلسله‌مراتب، کنتراست

## محدودیت‌ها

- فقط HTML و CSS؛ بدون JavaScript و بدون فریم‌ورک
- همه‌ی رنگ‌ها و فاصله‌ها از CSS Variables بیایند (بدون عدد تصادفی)
- اندازه‌ی فونت و فاصله‌ها با `rem`
- بدون `id` برای استایل‌دهی و بدون `!important`
- هیچ تصویری بدون `alt` مناسب

## معیار قبولی

- در عرض‌های ۳۲۰، ۷۶۸ و ۱۴۴۰ پیکسل چیدمان سالم است و اسکرول افقی ندارد
- ساختار Headingها درست است و فقط یک `h1` دارد
- نسبت کنتراست متن‌ها حداقل ۴.۵ به ۱ است (با DevTools بسنج)
- همه‌ی لینک‌ها و دکمه‌ها `:hover` و `:focus-visible` واضح دارند
- فقط با کیبورد (Tab) می‌توانی کل صفحه را بپیمایی
- کد HTML در `validator.w3.org` بدون خطا است
- با زوم ۲۰۰٪ مرورگر چیزی از هم نمی‌پاشد

## چک‌لیست بازبینی (Review)

- [ ] از المان‌های Semantic استفاده شده است، نه فقط `div`
- [ ] هیچ مقدار رنگ یا فاصله‌ای خارج از Variables نوشته نشده است
- [ ] تصاویر `width` و `height` یا `aspect-ratio` دارند و صفحه هنگام لود نمی‌پرد
- [ ] کارت‌های محصول با Grid چیده شده‌اند و در موبایل زیر هم قرار می‌گیرند
- [ ] دکمه‌ها `<button>` یا `<a>` واقعی‌اند (نه `div`)
- [ ] فاصله‌ها با یک مقیاس (مضرب ۴ یا ۸) تنظیم شده‌اند

## چالش‌های اختیاری

- تم تیره با `prefers-color-scheme`
- `scroll-behavior: smooth` برای لینک‌های داخلی
- انیمیشن ظریف `hover` روی کارت‌ها (با رعایت `prefers-reduced-motion`)
- بهینه‌سازی تصاویر با `picture` و `srcset`

## اشتباهات رایج

- طراحی فقط برای دسکتاپ و «چسباندن» موبایل در آخر
- استفاده از `px` برای اندازه‌ی فونت
- نبود حالت `focus` برای عناصر تعاملی
- تکرار کد کارت‌ها به‌جای کلاس مشترک (`.card`)

این نمونه، کد واقعی پروژه‌ی FitZone است که بازبینی و با تست مرورگر (Chromium) بررسی شده است. جدول زیر **تغییرهای اعمال‌شده** را نشان می‌دهد؛ هر کدام یک درس عمومی برای پروژه‌های بعدی تو هم هست.

### نقاط قوت

- ساختار صفحه کامل و Semantic است (`header`، `nav`، `main`، `section`، `footer`)
- CSS Variables منظم و کامنت‌گذاری‌شده (رنگ، فاصله، شعاع، سایه)
- فایل‌های جدا برای `normalize.css` و `style.css`
- Responsive با چند Breakpoint و Header چسبنده (Sticky)
- بخش‌بندی روشن و ظاهر یکدست

### مشکل‌های پیداشده و اصلاح‌ها

| مشکل | چرا مهم است | اصلاح |
|------|-------------|-------|
| `font-family` هیچ‌جا تنظیم نشده بود | مرورگر با فونت Serif (Times) نمایش می‌داد | یک Font Stack و `body { font-size: 1.6rem }` (چون `html` روی `62.5%` است، بدون این خط متن‌های بی‌اندازه ۱۰px می‌شوند) |
| متن سفید روی `#4caf50` (کنتراست ۲.۷۸ به ۱) و در `hover` ۴.۱۲ | زیر حداقل ۴.۵ است؛ برای کم‌بینایان خوانا نیست | رنگ دکمه `#2e7d32` (۵.۱۳) و `hover` برابر `#1b5e20` |
| اسکرول افقی در عرض ۳۲۰px | `width: 100%` همراه با `padding` بدون `box-sizing: border-box` از والد بیرون می‌زند | `*, *::before, *::after { box-sizing: border-box }` |
| لینک «About» به `#footer` می‌رفت و `#why` در Footer مقصد نداشت | لینک شکسته | `id="why"` روی بخش، و لینک «About» به آن |
| دکمه‌های «Shop Now» و «Explore Products» فقط `<button>` بودند و کاری نمی‌کردند | چیزی که «رفتن به جای دیگر» است، لینک است | `<a href="#products">` |
| نشان برند با `<h3>` قبل از `<h1>` | ترتیب Heading خراب می‌شود | `<a class="brand">`؛ عنوان‌های Footer شدند `h2` |
| کارت محصول با `<figure>` | `figure` برای رسانه‌ی همراه کپشن است | `<article>` |
| `.Products` و `id="Products"` با حرف بزرگ | ناهماهنگ با بقیه‌ی نام‌ها | `products` |
| نام فایل تصویر با فاصله و حرف بزرگ (`Premium Dumbbells.jpg`) | روی سرور لینوکس حساس به حروف بزرگ و کوچک مشکل می‌سازد | `premium-dumbbells.jpg` |
| تصاویر بدون `width` / `height` | هنگام لود صفحه می‌پرد (Layout Shift) | ابعاد اضافه شد؛ تصاویر محصول `loading="lazy"` |
| لینک‌های داخلی زیر هدر Sticky پنهان می‌شدند | عنوان بخش زیر هدر می‌رفت | `scroll-margin-top` |
| نبودن حلقه‌ی فوکوس سفارشی و `prefers-reduced-motion` | کاربر کیبورد و کاربر حساس به حرکت | `:focus-visible` و `@media (prefers-reduced-motion)` |
| تلفن و ایمیل Footer فقط متن بودند | قابل‌کلیک نبودند | `tel:` و `mailto:` |
| `<title>` ساده و بدون `meta description` | SEO و نمایش در تب | هر دو بهتر شدند |
| `.main { display: flex ... }` و `height: 100%` بی‌اثر | کد اضافی | حذف شد |

### نکته‌هایی که تصمیمش با خودت است

- Breakpointها **Desktop-First** (`max-width`) هستند. چون هدف پروژه Mobile-First بود، یک بار بازنویسی با `min-width` تمرین خوبی است.
- تصویر Hero فقط ۱۹۳×۱۴۸ پیکسل است و بزرگ‌تر نمایش داده می‌شود (تار). تصویر بزرگ‌تر (حداقل ۱۰۰۰px عرض) بگذار؛ ضمناً موضوع تصویر (راکت تنیس) با «تجهیزات تمرین» جور نیست.
- `transition: 0.3s ease` همه‌ی ویژگی‌ها را انیمیت می‌کند؛ ویژگی‌های مشخص (`transform`، `background-color`) بنویس.

### درس‌هایی که به پروژه‌های بعدی منتقل می‌شود

- همیشه `box-sizing: border-box`، `font-family` و کنتراست را در همان ابتدا بررسی کن
- هر چیزی که «می‌رود به جایی» لینک است و هر چیزی که «کاری انجام می‌دهد» دکمه
- هر لینک داخلی (`#...`) را یک بار کلیک کن و مطمئن شو مقصد دارد
