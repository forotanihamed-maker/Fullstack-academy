# Movie Explorer — AI Edition

> **سطح:** متوسط تا پیشرفته  
> **مرحله:** JavaScript / Async / Fetch / API  
> **وضعیت:** نمونه‌ی کامل (نسخه‌ی دوم همان بریف)  
> **API:** OMDb (`omdbapi.com`)  
> **زمان پیشنهادی:** ۷ تا ۱۲ روز  
> **پیش‌نیاز:** فصل ۵ (Async و Promise) و فصل ۶ (Fetch، HTTP و API)

## هدف

ساخت یک اپلیکیشن واقعی جستجوی فیلم و سریال با یک API خارجی؛ با تمرکز روی چیزهایی که در پروژه‌های تمرینی دیده نمی‌شوند: **Loading**، **Empty**، **Error**، **لغو درخواست قدیمی** و **دسترس‌پذیری مودال**.

این نسخه، برداشت دوم از همان بریف پروژه‌ی `Movie Explorer` است و کنار نسخه‌ی ساده‌تر گذاشته شده تا تفاوت تصمیم‌های طراحی را ببینی.

## قابلیت‌ها

- جستجو از فرم اصلی (Hero) و از نوار جستجوی هدر
- **جستجوی زنده با Debounce** در هدر (۵۰۰ میلی‌ثانیه، حداقل ۲ کاراکتر)
- شبکه‌ی کارت پوستر با عنوان، سال و برچسب نوع (movie / series)
- **مودال جزئیات** با پوستر، مدت، رده‌ی سنی، کارگردان، بازیگران، ژانر، امتیاز IMDb، فروش و خلاصه
- **Skeleton Loading** هنگام جستجو و Spinner هنگام باز شدن جزئیات
- حالت‌های دوستانه: «نتیجه‌ای پیدا نشد»، «نتیجه‌ها زیاد است»، خطای شبکه و خطای HTTP
- **`AbortController`** برای لغو جستجوهای قدیمی و درخواست جزئیات قبلی
- پوستر جایگزین به‌صورت SVG درون‌خطی (بدون سرویس خارجی)
- دسترس‌پذیری: کارت‌ها `<button>` واقعی‌اند، مودال `aria-modal` دارد، Tab داخل مودال می‌ماند، `Esc` می‌بندد و فوکوس به کارت قبلی برمی‌گردد
- پاک‌سازی (Escape) همه‌ی متن‌های آمده از API قبل از تزریق به HTML
- چیدمان Responsive و احترام به `prefers-reduced-motion`

## بخش‌های مهم کد

### ۱) لایه‌ی API و خطاهای تایپ‌دار

```js
class ApiError extends Error {
  constructor(message, type) {
    super(message);
    this.name = "ApiError";
    this.type = type; // "network" | "http" | "api"
  }
}
```

نکته‌ی مهم OMDb: خطاهای منطقی را با **HTTP 200** و `"Response": "False"` برمی‌گرداند؛ پس `response.ok` تنها کافی نیست:

```js
const data = await response.json();
if (data.Response === "False") {
  throw new ApiError(data.Error || "Unknown API error.", "api");
}
```

### ۲) Debounce و AbortController

```js
const debouncedLiveSearch = debounce(() => {
  runSearch(headerInput.value);
}, DEBOUNCE_MS);

headerInput.addEventListener("input", debouncedLiveSearch);
```

داخل `runSearch` اول درخواست قبلی لغو می‌شود تا پاسخ قدیمی روی نتیجه‌ی جدید ننشیند:

```js
state.searchController?.abort();
const controller = new AbortController();
state.searchController = controller;
```

و در `catch`، خطای `AbortError` نادیده گرفته می‌شود؛ چون لغو عمدی است، نه خطای کاربر.

### ۳) حالات UI جدا از هم

| وضعیت | چه چیزی نمایش داده می‌شود |
|-------|----------------------------|
| شروع | راهنمای جستجو (بخش Hero) |
| کوتاه‌تر از ۲ حرف | پیام «Keep typing» و بدون درخواست |
| Loading | ۸ کارت Skeleton |
| نتیجه | کارت فیلم‌ها + شمارش نتایج |
| Empty (`Movie not found!`) | پیام «No matches found» با عبارت جستجو |
| Too many (`Too many results.`) | پیام «عبارت را کامل‌تر بنویس» |
| خطا | پیام مناسب + امکان اصلاح جستجو |

### ۴) مودال و دسترس‌پذیری

- بستن با دکمه، کلیک روی Backdrop یا `Esc`
- به‌خاطر سپردن عنصر فوکوس‌شده و برگرداندن فوکوس بعد از بسته شدن
- نگه‌داشتن `Tab` / `Shift+Tab` داخل مودال
- پاک‌سازی محتوای مودال هنگام بستن (تا داده‌ی فیلم قبلی لحظه‌ای دیده نشود)

### ۵) پوستر جایگزین

به‌جای سرویس Placeholder، یک SVG به‌صورت `data:` ساخته می‌شود. اگر آدرس پوستر `"N/A"` باشد یا تصویر لود نشود، همین SVG نمایش داده می‌شود:

```js
const FALLBACK_POSTER =
  "data:image/svg+xml;charset=UTF-8," + encodeURIComponent(/* svg */);

img.addEventListener("error", () => { img.src = FALLBACK_POSTER; }, { once: true });
```

| سناریو | رفتار درست |
|--------|-------------|
| جستجوی `Inception` | کارت‌ها با عنوان، سال و پوستر نمایش داده می‌شوند |
| جستجوی `zzzzqqq` | حالت Empty، نه خطا |
| جستجوی `ba` (۲ حرف) | درخواستی ارسال نمی‌شود |
| تایپ سریع `batman` | فقط آخرین درخواست کامل می‌شود و بقیه در Network با `canceled` علامت می‌خورند |
| قطع اینترنت در DevTools | پیام خطای شبکه، بدون نشت Promise ردشده |
| فیلم بدون پوستر (`Poster: "N/A"`) | پوستر جایگزین SVG |
| فیلم بدون خلاصه | خط تیره به‌جای متن خالی |
| کلیک روی کارت و بستن با `Esc` | فوکوس به همان کارت برمی‌گردد، اسکرول صفحه سر جایش است |
| متن حاوی `<script>` در داده | به‌صورت متن نمایش داده می‌شود، اجرا نمی‌شود |
| ورودی خالی یا فقط فاصله | هیچ درخواستی ارسال نمی‌شود |

## محدودیت‌ها

- بدون فریم‌ورک و بدون کتابخانه؛ فقط JavaScript خالص
- همه‌ی متن‌های API از `escapeHtml` عبور می‌کنند
- `AbortError` هرگز به کاربر نشان داده نمی‌شود
- کلید API فقط برای این نمونه‌ی آموزشی رایگان است؛ در پروژه‌ی واقعی نباید در Front-End بماند

## نمونه‌ی زنده و بازبینی کد

[باز کردن نمونه‌ی زنده‌ی Movie Explorer — AI](/demos/movie-explorer-ai/index.html)

این نمونه همان کد پروژه است و با تست دستی در مرورگر (Chromium) بررسی شده است.

### نقاط قوت

- جداسازی روشن بین لایه‌ی API، وضعیت برنامه و رندر UI
- `ApiError` با `type` مشخص، به‌جای پیام‌های رشته‌ای پراکنده
- لغو درخواست‌ها با `AbortController` در هر دو مسیر (جستجو و جزئیات)
- Skeleton و Spinner واقعی به‌جای متن «Loading...»
- پاک‌سازی همه‌ی داده‌های خارجی با `escapeHtml`
- مودال کامل از نظر دسترس‌پذیری (فوکوس، `aria-modal`, `Esc`, Tab trap)
- تصویر جایگزین بدون وابستگی به سرویس بیرونی

### تفاوت‌های کلیدی با نسخه‌ی ساده (`Movie Explorer`)

| موضوع | نسخه‌ی ساده | نسخه‌ی AI |
|-------|-------------|-----------|
| ساختار | یک فایل بزرگ | لایه‌بندی API / State / Render در همان فایل با بخش‌بندی روشن |
| خطا | بررسی `response.ok` | خطای شبکه، HTTP و خطای منطقی OMDb جدا |
| Loading | متن ساده | Skeleton کارت + Spinner مودال |
| لغو درخواست | ندارد یا ناقص | `AbortController` برای جستجو و جزئیات |
| مودال | بدون مدیریت فوکوس | `aria-modal`، Focus Trap، بازگشت فوکوس |
| تصویر جایگزین | سرویس خارجی | SVG درون‌خطی |
| لایه‌ی داده | فیلدهای API مستقیم در UI | نگاشت و مقادیر پیش‌فرض در لایه‌ی API |
| تست | دستی و پراکنده | جدول سناریوهای مشخص |

### درس‌هایی که به پروژه‌های بعدی منتقل می‌شود

- `response.ok` را با خطای منطقی API اشتباه نگیر؛ بعضی APIها خطا را با ۲۰۰ برمی‌گردانند
- هر درخواست ناهمگام باید راهی برای لغو داشته باشد
- برای هر لیست، چهار حالت `idle`، `loading`، `empty` و `error` را از ابتدا طراحی کن
- عنصر فوکوس‌شده را قبل از باز کردن مودال ذخیره و بعد از بستن برگردان
- هر داده‌ای که از بیرون می‌آید، حتی اگر «قابل‌اعتماد» به‌نظر برسد، قبل از HTML پاک‌سازی شود

## چالش‌های اختیاری

- صفحه‌بندی یا «بیشتر نشان بده» با پارامتر `page`
- علاقه‌مندی‌ها در `localStorage`
- همگام‌سازی عبارت جستجو با آدرس (`URLSearchParams`)
- کش ساده با `Map` برای جستجوهای تکراری
- فیلتر بر اساس نوع (movie / series) و سال
