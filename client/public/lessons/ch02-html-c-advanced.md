# فصل ۲: HTML — بخش C: پیشرفته

## ۲.۱۶ Accessibility (دسترس‌پذیری) `[ضروری]`

**مفهوم.** دسترس‌پذیری (به اختصار a11y) یعنی صفحه برای همه قابل‌استفاده باشد: کاربران نابینا (screen reader)، کم‌بینا، کسانی که فقط با کیبورد کار می‌کنند، ناشنوا، کاربران با محدودیت حرکتی، و حتی کسی که روی موبایل زیر آفتاب است. این موضوع فقط «کار اخلاقی» نیست؛ بخشی از کیفیت حرفه‌ای و در بسیاری از کشورها الزام قانونی است.

**چهار اصل (POUR):** محتوا باید قابل‌درک (Perceivable)، قابل‌استفاده (Operable)، قابل‌فهم (Understandable) و مقاوم (Robust) باشد.

> **قانون اول:** تا جایی که المان HTML بومی وجود دارد، از آن استفاده کن. ARIA آخرین راه است، نه اولین.

### ساختار صحیح Headingها

screen reader کاربران را با فهرست Headingها هدایت می‌کند، پس Headingها باید نقشه‌ی منطقی صفحه باشند.

- ترتیب را نشکن (`h1` ← `h2` ← `h3`) و فقط برای اندازه انتخاب نکن.
- یک `h1` که موضوع اصلی را بگوید (توصیه‌ی رایج).

### متن جایگزین تصاویر (`alt`)

| نوع تصویر | `alt` مناسب |
|-----------|-------------|
| اطلاعاتی (عکس محصول، نمودار) | توضیح کوتاه و معنادار: `alt="کفش دویدن آبی مدل X"` |
| تزئینی (خط جداکننده، پس‌زمینه‌ی تزئینی) | `alt=""` (خالی) تا نادیده گرفته شود |
| تصویر داخل لینک یا دکمه | مقصد یا عمل را بگو: `alt="صفحه‌ی اصلی"` نه «لوگو» |
| پیچیده (نمودار پرجزئیات) | `alt` کوتاه + توضیح کامل در متن کنار آن |

**قواعد:** «تصویر ...» یا «عکس ...» نگو (screen reader خودش می‌گوید)، و اگر تصویر متن دارد، آن متن را در `alt` بیاور.

### دسترسی با کیبورد

بسیاری از کاربران فقط با کیبورد کار می‌کنند. همه‌ی کارهایی که با ماوس ممکن است، باید با `Tab`، `Shift+Tab`، `Enter`، `Space` و `Esc` ممکن باشد.

- المان‌های بومی (`a`، `button`، `input`، `select`، `textarea`) خودکار focus می‌شوند. `div` و `span` نه.
- ترتیب Tab باید با ترتیب منطقی صفحه یکی باشد (ترتیب نوشتن در HTML).
- `tabindex="0"`: المان غیرتعاملی را وارد ترتیب Tab می‌کند (فقط وقتی لازم است).
- `tabindex="-1"`: المان را قابل‌فوکوس با JS می‌کند، ولی از ترتیب Tab خارج می‌کند.
- هرگز `tabindex` با مقدار مثبت (مثل `tabindex="3"`) استفاده نکن؛ ترتیب طبیعی را به‌هم می‌ریزد.
- Focus را نامرئی نکن (`outline: none` بدون جایگزین ممنوع؛ در CSS می‌بینی).

**لینک پرش (Skip Link):** به کاربر کیبورد اجازه می‌دهد از منوی طولانی بپرد:

```html
<body>
  <a href="#main" class="skip-link">پرش به محتوای اصلی</a>
  <header>...منوی طولانی...</header>
  <main id="main" tabindex="-1">...</main>
</body>
```

(ظاهر `skip-link` را بعداً با CSS تنظیم می‌کنیم؛ معمولاً تا زمان focus مخفی است.)

### فرم‌های قابل‌دسترس

علاوه بر `label` و `fieldset`، پیام راهنما و خطا را به فیلد وصل کن:

```html
<div>
  <label for="pass">رمز عبور</label>
  <input type="password" id="pass" name="pass"
         aria-describedby="pass-hint pass-error"
         aria-invalid="true" required />
  <p id="pass-hint">حداقل ۸ کاراکتر.</p>
  <p id="pass-error" role="alert">رمز عبور کوتاه است.</p>
</div>
```

**توضیح:**

- `aria-describedby` به چند `id` اشاره می‌کند؛ screen reader آن متن‌ها را بعد از `label` می‌خواند.
- `aria-invalid="true"` فیلد را نامعتبر اعلام می‌کند (فقط وقتی واقعاً خطا دارد).
- `role="alert"` باعث می‌شود وقتی متن خطا ظاهر شد، بلافاصله خوانده شود.
- خطا را فقط با رنگ قرمز نشان نده؛ متن هم بنویس.

### ARIA (در حد لازم) `[مفید/حرفه‌ای]`

ARIA مجموعه‌ی attributeهایی است که به فناوری‌های کمکی اطلاعات اضافه می‌دهد. **ARIA رفتار اضافه نمی‌کند؛ فقط معنا را اعلام می‌کند** (رفتار را باید خودت با JS بسازی).

| Attribute | کاربرد |
|-----------|--------|
| `aria-label` | نام دسترس‌پذیر وقتی متن قابل‌مشاهده نداریم (مثلاً دکمه‌ی فقط آیکن) |
| `aria-labelledby` | نام را از المان دیگری (با `id`) می‌گیرد |
| `aria-describedby` | توضیح اضافه از المان دیگر |
| `aria-expanded` | آیا بخش وابسته باز است؟ (`true` / `false`) |
| `aria-controls` | این المان کدام المان را کنترل می‌کند |
| `aria-hidden="true"` | المان را از screen reader پنهان می‌کند (فقط برای تزئینات) |
| `aria-live` | اعلام تغییرات پویا (مثل «۳ نتیجه پیدا شد») |
| `role` | تعیین نقش (فقط وقتی المان بومی ندارد) |

**مثال: دکمه‌ی باز و بسته کردن منو:**

```html
<button type="button" aria-expanded="false" aria-controls="menu">
  منو
</button>
<ul id="menu" hidden>
  <li><a href="/">خانه</a></li>
  <li><a href="/about">درباره</a></li>
</ul>
```

با JavaScript هنگام کلیک `aria-expanded` و `hidden` را تغییر می‌دهیم (در فصل DOM). حالت ARIA باید همیشه با وضعیت واقعی هماهنگ باشد.

**دکمه‌ی فقط آیکن:**

```html
<button type="button" aria-label="بستن پنجره">
  <svg aria-hidden="true" width="16" height="16"><!-- آیکن X --></svg>
</button>
```

**اشتباهات رایج**

- `<div role="button">` به‌جای `<button>` (باید Enter، focus و Space را هم خودت بسازی؛ بی‌دلیل سخت‌ترش می‌کنی).
- `aria-hidden="true"` روی المان قابل‌فوکوس (کاربر focus می‌کند ولی چیزی نمی‌شنود).
- ARIA اشتباه بدتر از نبودنش است. «ARIA ندارم» بهتر از «ARIA غلط» است.
- فراموش کردن `lang` صفحه.
- تکیه بر رنگ برای انتقال معنا.
- حذف outline فوکوس.

**تمرین کوچک:** صفحه‌ای که ساخته‌ای را فقط با کیبورد پیمایش کن (ماوس را کنار بگذار). آیا همه‌چیز قابل‌دسترسی است؟ فوکوس همیشه دیده می‌شود؟ ترتیب Tab منطقی است؟ بعد در DevTools (تب Accessibility) یا ابزار Lighthouse امتیاز دسترس‌پذیری را ببین.

## ۲.۱۷ مبانی SEO و تگ‌های meta `[مفید/حرفه‌ای]`

**مفهوم.** SEO یعنی کمک به موتورهای جستجو برای فهمیدن صفحه. در سطح HTML، بخش عمده‌ی آن همان Semantic و Accessibility درست است.

```html
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>آموزش Flexbox از صفر | وبلاگ فرانت‌اند</title>
  <meta name="description"
        content="آموزش گام‌به‌گام Flexbox با مثال‌های واقعی برای چیدمان صفحه." />
  <link rel="canonical" href="https://example.com/flexbox" />
  <link rel="icon" href="/favicon.ico" />

  <!-- Open Graph: ظاهر لینک در شبکه‌های اجتماعی و پیام‌رسان‌ها -->
  <meta property="og:title" content="آموزش Flexbox از صفر" />
  <meta property="og:description" content="آموزش گام‌به‌گام Flexbox با مثال‌های واقعی." />
  <meta property="og:image" content="https://example.com/images/flexbox-cover.jpg" />
  <meta property="og:url" content="https://example.com/flexbox" />
  <meta property="og:type" content="article" />
</head>
```

| تگ | کاربرد |
|----|--------|
| `title` | مهم‌ترین عنصر `head`؛ یکتا و توصیفی (حدوداً ۵۰ تا ۶۰ کاراکتر معمولاً بدون برش نمایش داده می‌شود) |
| `meta description` | خلاصه‌ی صفحه در نتایج جستجو (حدود ۱۵۰ تا ۱۶۰ کاراکتر؛ تضمینی برای نمایش نیست) |
| `viewport` | سازگاری با موبایل (ضروری) |
| `canonical` | آدرس اصلی، وقتی چند آدرس محتوای یکسان دارند |
| `og:*` | پیش‌نمایش در اشتراک‌گذاری |
| `robots` (`noindex`) | جلوگیری از ایندکس صفحه (مثلاً صفحه‌ی ورود) |

**درباره‌ی `viewport`:** مقدار `width=device-width, initial-scale=1` یعنی «عرض صفحه برابر عرض دستگاه». از `user-scalable=no` یا `maximum-scale=1` استفاده نکن؛ زوم کردن را از کم‌بینایان می‌گیرد.

**شاخص‌های SEO که در HTML دست توست:** `title` و `description` یکتا برای هر صفحه، Heading درست، `alt` برای تصاویر، متن لینک توصیفی، ساختار Semantic، سرعت، و سازگاری با موبایل.

> **خارج از این جزوه:** SEO عمیق فنی (sitemap، robots.txt، Structured Data/Schema، SSR، رتبه‌بندی). فعلاً همین مبانی کافی است.

**اشتباهات رایج**

- `title` تکراری در همه‌ی صفحه‌ها؛ `description` خالی.
- تصویر `og:image` با آدرس نسبی (باید آدرس کامل باشد).
- Keyword Stuffing (تکرار بی‌معنی کلمه‌ی کلیدی). مخاطب اصلی خوانندگان‌اند.
- باور اینکه `meta keywords` هنوز تأثیر دارد (موتورهای جستجوی اصلی آن را نادیده می‌گیرند).

**تمرین کوچک:** برای هر صفحه‌ی پروژه‌ات `title` و `description` یکتا بنویس. آدرس صفحه را در یک پیام‌رسان بفرست (وقتی منتشر شد) و پیش‌نمایش `og:*` را ببین.

## ۲.۱۸ عناصر چندرسانه‌ای و تصاویر واکنش‌گرا `[مفید/حرفه‌ای]`

### `iframe`: تعبیه‌ی صفحه‌ی دیگر

```html
<iframe
  src="https://www.openstreetmap.org/export/embed.html?bbox=..."
  title="نقشه‌ی موقعیت دفتر"
  width="600" height="400"
  loading="lazy"
  referrerpolicy="no-referrer"
></iframe>
```

- `title` (برای screen reader الزامی).
- `loading="lazy"`: بارگذاری تا نزدیک شدن به دید کاربر به تعویق می‌افتد.
- `sandbox` محدودیت امنیتی روی محتوای تعبیه‌شده می‌گذارد (وقتی از منبع نیمه‌معتمد استفاده می‌کنی).

> **امنیت:** هر `iframe` یعنی اجرای محتوای شخص دیگر در صفحه‌ی تو. فقط از منابع معتبر. بعضی سایت‌ها اصلاً اجازه‌ی تعبیه نمی‌دهند (خارج از این جزوه: هدرهای سرور).

### `video` و `audio`

```html
<video controls width="640" poster="cover.jpg" preload="metadata">
  <source src="lesson.webm" type="video/webm" />
  <source src="lesson.mp4" type="video/mp4" />
  <track kind="captions" src="lesson-fa.vtt" srclang="fa" label="فارسی" default />
  مرورگر شما از ویدیو پشتیبانی نمی‌کند.
</video>

<audio controls>
  <source src="podcast.mp3" type="audio/mpeg" />
  مرورگر شما از پخش صوت پشتیبانی نمی‌کند.
</audio>
```

| Attribute | معنی |
|-----------|------|
| `controls` | نوار کنترل پخش |
| `poster` | تصویر پیش از پخش |
| `preload` | `auto` / `metadata` / `none` (چقدر از قبل بارگذاری شود) |
| `autoplay` | پخش خودکار (مرورگرها عموماً فقط با `muted` اجازه می‌دهند؛ و برای کاربر آزاردهنده است) |
| `muted`، `loop` | بی‌صدا، تکرار |
| `<track>` | زیرنویس و توضیح برای ناشنوایان (دسترس‌پذیری) |

چند `source`: مرورگر اولین فرمتی را که پشتیبانی می‌کند انتخاب می‌کند.

### `source`، `picture` و تصاویر واکنش‌گرا

**مسئله:** یک تصویر ۲۰۰۰ پیکسلی روی موبایل بی‌دلیل سنگین است.

**راه‌حل ۱:** `srcset` و `sizes` (انتخاب اندازه‌ی مناسب):

```html
<img
  src="photo-800.jpg"
  srcset="photo-400.jpg 400w, photo-800.jpg 800w, photo-1600.jpg 1600w"
  sizes="(max-width: 600px) 100vw, 50vw"
  alt="کوهستان در غروب"
  width="800" height="533"
  loading="lazy"
/>
```

- `srcset`: لیست نسخه‌ها همراه با عرض واقعی هر فایل (`w`).
- `sizes`: به مرورگر می‌گوید تصویر در صفحه چه عرضی خواهد داشت. روی موبایل کل عرض، در غیر این صورت نصف. مرورگر خودش بهترین فایل را انتخاب می‌کند.

**راه‌حل ۲:** `picture` (فرمت‌های مدرن و Art Direction):

```html
<picture>
  <source srcset="hero.avif" type="image/avif" />
  <source srcset="hero.webp" type="image/webp" />
  <source media="(max-width: 600px)" srcset="hero-mobile.jpg" />
  <img src="hero.jpg" alt="تیم ما در حال کار" width="1200" height="600" />
</picture>
```

مرورگر اولین `source` مناسب را می‌گیرد؛ اگر هیچ‌کدام نشد، `img` پایانی. `img` الزامی است و `alt` را آن می‌دهد.

**فرق `srcset` و `picture`:** `srcset` یک تصویر را در اندازه‌های مختلف عرضه می‌کند؛ `picture` وقتی لازم است فرمت یا کادر (crop) متفاوت بدهی.

### Lazy Loading و جلوگیری از «پرش» صفحه

- `loading="lazy"` برای تصاویر و `iframe`های پایین‌تر از دید اولیه.
- برای تصویر بزرگ بالای صفحه (hero)، `lazy` نگذار؛ سریع باید بیاید.
- همیشه `width` و `height` بنویس؛ مرورگر قبل از لود فضا را رزرو می‌کند و صفحه «نمی‌پرد» (Layout Shift).

**اشتباهات رایج**

- `iframe` بدون `title`.
- `autoplay` با صدا.
- ویدیو بدون زیرنویس برای محتوای آموزشی.
- `lazy` برای تصویر اول صفحه.
- فایل تصویر بزرگ‌تر از نیاز.
- فراموش کردن `img` داخل `picture`.

**تمرین کوچک:** یک تصویر را با `picture` و دو فرمت (JPG + WebP) و یک نسخه‌ی موبایل بارگذاری کن. در DevTools تب Network ببین مرورگر کدام فایل را گرفت و با تغییر عرض پنجره چه عوض می‌شود.

## ۲.۱۹ `data-*` Attribute، `template`، `dialog`، `details`/`summary` `[مفید/حرفه‌ای]`

### `data-*` Attributes

برای نگه‌داشتن اطلاعات دلخواه روی المان (مفید برای JavaScript):

```html
<button type="button" class="add-to-cart" data-product-id="42" data-price="250000">
  افزودن به سبد
</button>
```

با JavaScript: `button.dataset.productId` و `button.dataset.price` (نام `data-product-id` به `productId` تبدیل می‌شود؛ در فصل DOM). همچنین می‌توان با CSS انتخابشان کرد.

> **هشدار:** `data-*` برای اطلاعات غیرحساس است؛ هر کاربری آن را می‌بیند و می‌تواند تغییر دهد. قیمت واقعی را هیچ‌وقت از آن نخوان و به آن اعتماد نکن.

### `template`

قالب HTML که نمایش داده نمی‌شود و به‌صورت قالب برای JavaScript نگه داشته می‌شود:

```html
<template id="product-card-template">
  <article class="card">
    <h3 class="card__title"></h3>
    <p class="card__price"></p>
  </article>
</template>
```

با JS محتوای آن را کلون و پر می‌کنیم (فصل DOM). مزیت: HTML قالب را از منطق JS جدا نگه می‌دارد.

### `dialog`: پنجره‌ی گفتگو (Modal)

```html
<button type="button" id="open-btn">باز کردن</button>

<dialog id="confirm-dialog">
  <h2>حذف حساب</h2>
  <p>آیا مطمئن هستید؟</p>
  <form method="dialog">
    <button value="cancel">انصراف</button>
    <button value="confirm">حذف</button>
  </form>
</dialog>

<script>
  const dialog = document.getElementById("confirm-dialog");
  document.getElementById("open-btn").addEventListener("click", () =>
    dialog.showModal());
</script>
```

- `showModal()` پنجره را به‌صورت Modal باز می‌کند: پس‌زمینه غیرقابل‌تعامل می‌شود، با `Esc` بسته می‌شود و فوکوس را مدیریت می‌کند.
- `<form method="dialog">` با کلیک دکمه، پنجره را می‌بندد و `value` دکمه را به‌عنوان `returnValue` می‌دهد.
- **قدیمی در برابر مدرن:** ساختن Modal با `div` و مدیریت دستی فوکوس و `Esc`، کار سختی است و باگ دسترس‌پذیری زیاد دارد. `dialog` را ترجیح بده.

### `summary` / `details`: آکاردئون ساده بدون JS

```html
<details>
  <summary>آیا HTML زبان برنامه‌نویسی است؟</summary>
  <p>خیر؛ زبان نشانه‌گذاری است.</p>
</details>
```

- `open` در `details` یعنی پیش‌فرض باز.
- داخل `summary` فقط محتوای عبارتی (متن و عناصر ساده) بگذار.
- گروه‌بندی چند `details` به‌صورت «فقط یکی باز باشد» (با `name` attribute) در مرورگرهای جدید در دسترس است؛ پیش از استفاده، پشتیبانی را در MDN یا `caniuse.com` بررسی کن. `[پیشرفته/اختیاری]`

**اشتباهات رایج**

- گذاشتن داده‌ی حساس یا قیمت واقعی در `data-*`.
- `template` را با «المان مخفی» اشتباه گرفتن: محتوای `template` اصلاً بخشی از صفحه‌ی فعال نیست.
- ساختن Modal با `div` در حالی که `dialog` وجود دارد.
- ندادن نام دسترس‌پذیر به `dialog` (باید Heading یا `aria-label` داشته باشد).

**تمرین کوچک:** یک بخش FAQ با سه `details` بساز. یک `dialog` تأیید حذف بساز و با دو دکمه‌ی «انصراف» و «حذف» ببند. (کد JS لازم برای باز کردن `dialog` در همین متن آمده است.)

## ۲.۲۰ Performance و Best Practices در HTML `[مفید/حرفه‌ای]`

### جای `script` و `defer` / `async`

مرورگر هنگام رسیدن به `<script>` معمولاً پردازش HTML را متوقف می‌کند تا آن را دانلود و اجرا کند. این دو مشکل می‌سازد: کندی نمایش صفحه، و اجرای اسکریپت قبل از ساخته شدن المان‌ها.

> **پاسخ سؤال ۶ فصل ۱:** اگر `<script>` قبل از `<h1>` باشد و کدش `document.getElementById("t")` را صدا بزند، المان هنوز ساخته نشده و نتیجه `null` است؛ استفاده از `textContent` روی آن خطای `Cannot read properties of null` می‌دهد.

| روش | رفتار |
|-----|-------|
| `<script src="a.js">` (در `head`) | HTML متوقف می‌شود، اجرا بلافاصله ← خطر `null` |
| `<script src="a.js">` (آخر `body`) | کار می‌کند، ولی دانلود دیرتر شروع می‌شود |
| `<script src="a.js" defer>` | دانلود موازی، اجرا بعد از تمام شدن پارس HTML، به‌ترتیب نوشتن |
| `<script src="a.js" async>` | دانلود موازی، اجرا به‌محض آماده‌شدن (ترتیب تضمین نیست) |
| `<script type="module">` | رفتاری شبیه `defer` (فصل Modules) |

**توصیه:** برای اسکریپت‌های خودت `defer` را در `head` بگذار:

```html
<head>
  <link rel="stylesheet" href="css/style.css" />
  <script src="js/main.js" defer></script>
</head>
```

`async` برای اسکریپت‌های مستقل (مثل آنالیتیکس) مناسب است، نه برای کدی که به ترتیب یا به DOM وابسته است.

### قواعد عملکرد پایه

- تصاویر را بهینه (حجم کم، فرمت مدرن، اندازه‌ی مناسب) و lazy کن.
- `width` و `height` تصاویر را بنویس.
- CSS را در `head` و JS را با `defer` بارگذاری کن.
- تعداد المان‌های DOM را بی‌دلیل زیاد نکن.
- از فونت‌ها و کتابخانه‌های غیرضروری پرهیز کن.

(مباحث عمیق‌تر: فصل Performance Basics.)

### Best Practices کلی

- نام تگ و attribute را با حروف کوچک بنویس؛ مقدار attributeها را داخل `"` بگذار.
- تورفتگی منظم و یکسان (۲ یا ۴ فاصله).
- از `id` برای انتخاب استایل استفاده نکن (در CSS می‌بینی چرا).
- هر صفحه را با validator بررسی کن.
- ابتدا محتوا و معنا، سپس ظاهر.
- ساختار را طوری بنویس که بدون CSS هم خوانا و منطقی باشد.

### مطالب منسوخ؛ جایگزین‌های امروزی

| منسوخ | جایگزین |
|-------|---------|
| `<center>` | CSS (`text-align`، Flexbox) |
| `<font>`، attributeهای `bgcolor`، `align` | CSS |
| `<big>`، `<strike>` | `<s>` / `<del>` یا CSS |
| `<marquee>`، `<blink>` | CSS animation (با رعایت دسترس‌پذیری) |
| `<frame>`، `<frameset>` | `<iframe>` یا معماری جدید |
| `<acronym>` | `<abbr>` |
| چیدمان با `<table>` | Flexbox و Grid |
| Modal با `div` و جاوااسکریپت پیچیده | `<dialog>` |

## ۲.۲۱ چک‌لیست مهارتی HTML

با یک بار مرور صادقانه، هر مورد را علامت بزن. اگر نتوانی بدون کمک انجامش بدهی، علامت نزن.

### ساختار و پایه `[ضروری]`

- [ ] ساختار کامل سند را از حفظ می‌نویسم و می‌دانم هر بخش چه می‌کند.
- [ ] تفاوت `head` و `body` و نقش `lang`، `charset` و `viewport` را می‌دانم.
- [ ] Headingها را بر اساس معنا و با سلسله‌مراتب درست استفاده می‌کنم.
- [ ] لینک مطلق و نسبی و پرش با `#id` را درست می‌سازم.
- [ ] `alt` مناسب برای تصاویر اطلاعاتی، تزئینی و لینک‌دار می‌نویسم.
- [ ] تفاوت `class` و `id` و `a` و `button` را می‌توانم توضیح بدهم.

### Semantic و فرم `[ضروری]`

- [ ] چرا Semantic مهم است را با سه دلیل می‌گویم.
- [ ] `section` و `article` و `div` را درست انتخاب می‌کنم.
- [ ] یک فرم کامل با `label`، `fieldset`، `radio`، `select` و `checkbox` می‌سازم.
- [ ] تفاوت `id` و `name` و دلیل اهمیت `name` را می‌دانم.
- [ ] attributeهای اعتبارسنجی را به‌کار می‌برم و می‌دانم چرا امنیت نیست.

### پیشرفته `[ضروری و مفید]`

- [ ] صفحه‌ام را فقط با کیبورد پیمایش می‌کنم و همه‌چیز در دسترس است.
- [ ] می‌دانم ARIA چه موقع لازم است و چرا «اول المان بومی».
- [ ] `viewport`، `description`، `title` و `og:*` را درست می‌نویسم.
- [ ] `lazy`، `srcset`، `picture` و `width`/`height` تصاویر را می‌شناسم.
- [ ] تفاوت `defer` و `async` را توضیح می‌دهم.
- [ ] `template`، `details`، `dialog` و `data-*` را می‌شناسم و جای استفاده‌شان را می‌دانم.

> **نکته:** اگر چند مورد را نتوانستی علامت بزنی، پیش از رفتن به فصل CSS به بخش مربوطه برگرد. تسلط کامل بر ARIA و تمام مباحث اختیاری لازم نیست؛ تمرکز اصلی روی Semantic، فرم، `alt` و کیبورد باشد.

## تمرین‌های HTML پیشرفته

**ساده**

1. برای یک دکمه‌ی فقط آیکن، نام دسترس‌پذیر بنویس.
2. یک تصویر را با `srcset` در سه اندازه عرضه کن.
3. `defer` را به اسکریپت صفحه اضافه کن و تفاوت را در رفتار ببین.

**متوسط**

1. یک `dialog` تأیید حذف بساز که با دکمه‌ی «انصراف» و کلید `Esc` بسته شود.
2. یک ویدیوی آموزشی با `poster` و `track` زیرنویس بگذار.
3. `description`، `title` و `og:*` را برای سه صفحه‌ی متفاوت بنویس.

**چالشی**

1. با کیبورد و یک screen reader (NVDA در ویندوز، VoiceOver در مک) صفحه‌ات را بخوان و فهرستی از ۵ مشکل پیدا کن و رفع کن.
2. در تب Lighthouse مرورگر Chrome، امتیاز Accessibility و SEO صفحه را بگیر و تا بالای ۹۰ ببر.

## آیا HTML پیشرفته را بلدم؟

**سؤالات مفهومی**

1. چرا `<div role="button">` از `<button>` بدتر است؟ (دست‌کم سه دلیل)
2. چه فرقی بین `alt=""` و `alt` حذف‌شده برای screen reader وجود دارد؟
3. چرا `tabindex="5"` ایده‌ی بدی است؟
4. `aria-hidden="true"` را چه زمانی می‌توان روی یک المان گذاشت و چه زمانی نباید؟
5. تفاوت `srcset` و `picture` چیست؟
6. چرا `data-price` را نباید مبنای محاسبه‌ی قیمت نهایی قرار داد؟
7. تفاوت `defer` و `async` چیست و کدام برای کدی که به DOM وابسته است مناسب‌تر است؟

**تمرین کوتاه (کد را بخوان)**

8. این فرم چند مشکل دسترس‌پذیری دارد؟ آن‌ها را اصلاح کن.

```html
<div class="input">
  <input type="text" placeholder="ایمیل">
  <span style="color:red">خطا</span>
</div>
<div class="btn" onclick="send()">ارسال</div>
<img src="logo.png">
```

9. اگر کاربر روی موبایل با اینترنت کند وارد صفحه شود، کدام قسمت این کد باعث کندی یا پرش صفحه می‌شود؟

```html
<head>
  <script src="big-library.js"></script>
</head>
<body>
  <img src="hero-4000px.jpg" loading="lazy">
  <h1>عنوان</h1>
</body>
```

## پروژه‌ی سطح HTML پیشرفته: «صفحه‌ی محصول و Landing Page دسترس‌پذیر»

- **هدف:** ساخت دو صفحه (Landing Page یک محصول یا دوره + صفحه‌ی جزئیات محصول) که ساختاری حرفه‌ای، دسترس‌پذیر و آماده‌ی استایل‌دهی داشته باشند. (در فصل CSS همین دو صفحه را استایل می‌دهیم و Dashboard را هم اضافه می‌کنیم.)
- **امکانات:**
  - **Landing Page:** Hero با تصویر واکنش‌گرا، بخش ویژگی‌ها، بخش نظرات کاربران (`article` برای هر نظر)، FAQ با `details`، فرم عضویت در خبرنامه، `footer`.
  - **صفحه‌ی محصول:** گالری تصاویر با `figure`، مشخصات در `table`، دکمه‌ی «افزودن به سبد» با `data-*`، ویدیوی معرفی با زیرنویس، `dialog` برای تأیید افزودن.
  - **هر دو صفحه:** `description`، `title` و `og:*` اختصاصی؛ Skip Link؛ ناوبری با `aria-label`.
- **مهارت‌ها:** Semantic، فرم‌های قابل‌دسترس، مدیا و تصویر واکنش‌گرا، SEO پایه، `details`، `dialog`، `defer`.
- **محدودیت‌ها:** بدون CSS (فقط ساختار) و بدون کتابخانه؛ JavaScript فقط برای باز کردن `dialog` (حداکثر چند خط)؛ هیچ تصویری بدون `alt` مناسب؛ ARIA فقط وقتی المان بومی وجود ندارد و باید دلیلش در کامنت باشد.
- **معیار قبولی:**
  - هر دو صفحه بدون خطا در `validator.w3.org`.
  - امتیاز Accessibility در Lighthouse حداقل ۹۰.
  - کل صفحه فقط با کیبورد قابل‌استفاده است.
  - هیچ Heading خارج از ترتیب نیست و فقط یک `h1` دارد.
  - تصاویر زیر دید اولیه `lazy` هستند و همه `height` / `width` دارند.
  - بدون CSS هم محتوا منطقی و خوانا خوانده می‌شود.

## پاسخنامه‌ی مختصر (پس از تلاش خودت ببین)

**سؤال ۲:** `alt=""` یعنی «تزئینی است، نادیده بگیر»؛ بدون `alt` ممکن است screen reader نام فایل را بخواند.

**سؤال ۷:** `defer` (بعد از پارس HTML اجرا می‌شود و ترتیب حفظ می‌شود).

**سؤال ۸:** `placeholder` به‌جای `label`، خطا فقط با رنگ و بدون ارتباط با فیلد، `div` به‌جای `button` (focus و کیبورد ندارد)، تصویر بدون `alt`.

**سؤال ۹:** `script` بدون `defer` در `head` رندر را متوقف می‌کند؛ تصویر hero بالای صفحه `lazy` است (باید فوراً بیاید)؛ `height` / `width` ندارد؛ حجم تصویر زیاد است.
